Troubleshooting

Charticks 0.1.0 · Common problems and what to send when reporting one

Quick answers

What you seeWhat it usually meansWhat to do
“Windows protected your PC” on install The build is not code-signed. Click More info → Run anyway. Expected.
Window opens but everything is blank or zero No broker connected. Brokers screen → Add Broker → Connect. See BROKER-SETUP.html.
Prices show but never change Market is closed, or it is a trading holiday. Try 09:15–15:30 IST on a weekday. The app has no holiday calendar.
Broker dot is red Login failed. Re-check credentials. ICICI session keys expire daily.
Broker dot is amber Connecting, or session expired. Wait a few seconds, then Disconnect and Connect again.
Order fails: AG7002 … not a registered IP Your public IP is not whitelisted at Angel. Whitelist it on your SmartAPI app. See BROKER-SETUP.html.
Edited credentials but nothing changed The engine still holds the old ones. Disconnect the account, then Connect again.
Order shows OPEN, not EXECUTED Correct. The broker accepted it but has not filled it yet. Wait. It becomes EXECUTED or REJECTED once the broker decides.
Order shows REJECTED — Insufficient funds Your broker refused the order. Nothing was bought or sold. Add funds or trade fewer lots. No position is created — that is correct, not a missing position.
Live position doesn't appear right after the order Live positions are read from your broker every ~4 seconds. Wait a few seconds — but first check the order actually says EXECUTED, not OPEN or REJECTED.
Live position still missing after ~10 seconds The app could not read it from your broker. Check it exists in your broker's own Positions screen, then send application.log (below).
“Position still open — …” after clicking Close The broker rejected the closing order. The position is still open. Read the reason shown, and close it in your broker's terminal if unsure.
Stop Loss / Target not firing on a live position Live stops are enforced by this app from the price feed — so they need the app running and the feed alive. Check the feed is connected (status bar) and the position shows a live price. Then send application.log. See KNOWN-LIMITATIONS.html.
App window is blank / white The engine did not start. Close it fully and reopen. If it persists, send the log (below).

Where the log files are

From inside the app — no path to type. Go to Settings → Diagnostics:

  • Save Diagnostics ZIP — writes charticks-logs-<date>.zip to your Desktop and opens the folder with it selected. Attach that file to your report.
  • Open Logs Folder — opens the logs themselves in Explorer.

If the app will not start, the logs are still on disk. Paste this into the File Explorer address bar:

Documents\Charticks\logs

Send everything in that folder — the files are small. There are no date-named subfolders; each file is appended to as you use the app.

FileWhat it contains
application.log Every event, in order — the full narrative. Send this one first.
orders.log Orders: placed, modified, cancelled, filled or rejected, and why.
risk.log Why an order was refused — a limit you set, or a margin shortfall.
broker.log Logins, disconnects, reconnects and session expiry.
websocket.log Market-data feed: connects, interruptions and recovery.
exceptions.log Unexpected errors, with the full technical detail.
sidecar-process.log Written if the trading engine fails to start at all. If the app sits on "Connecting…", this is the file that says why.

If you were given an older instruction pointing at %APPDATA%\Charticks\logs, at %LOCALAPPDATA%\Programs\charticks\resources\sidecar\logs, or telling you to send "the newest date folder", or naming sidecar.log — those are all out of date. Use Settings → Diagnostics, or the folder above.

The logs moved to Documents so you can find them without digging through hidden folders. On a machine where Documents cannot be written, the app falls back to %APPDATA%\Charticks\logs — the Diagnostics panel always shows the path actually in use.

A live position is missing from the Positions grid

The app reads live positions from your broker every ~4 seconds, so they are never instant. Work through these:

  1. Check the order status first. In the app's Order Book the order must read EXECUTED. OPEN means the broker has it but has not filled it. REJECTED means the broker refused it — the reason is printed under the status, and there is correctly no position.
  2. Wait ~10 seconds and look again.
  3. Is the Positions panel in the right mode? The panel follows the Paper/Live switch, not the broker connection. Live positions only show in Live.
  4. Still missing while your broker clearly shows it — send application.log and orders.log. Together they record exactly what the broker returned and why a row was skipped.

The app opens but shows no data at all

Work through these in order:

  1. Is a broker connected? Brokers screen — the dot must be green. No connection means no data; the app has no prices of its own.
  2. Is the market open? 09:15–15:30 IST, Monday to Friday.
  3. Is it a holiday? The app cannot tell. Check the exchange calendar.
  4. Restart the app. Close it completely and reopen.
  5. Still nothing — send the log folder and a screenshot.

You do not need Python. If anyone suggests installing Python or running setup-tester.bat, that advice is for an older build. Version 0.1.0 has the engine built in. A missing Python installation cannot be the cause of any problem here.

Checking the engine is alive (advanced)

The trading engine runs locally on port 8787 and accepts connections only from your own machine. To confirm it is running, open PowerShell and run:

Invoke-WebRequest http://127.0.0.1:8787/health -UseBasicParsing

A healthy engine replies:

{"ok":true,"service":"charticks-sidecar","version":"0.1.0"}

If that fails while the app is open, the engine crashed — send the log folder.

Starting completely fresh

To wipe saved accounts and settings and start as if newly installed:

  1. Close Charticks completely.
  2. Open %APPDATA%\charticks.
  3. Delete brokers.json (this removes your saved broker accounts).
  4. Reopen the app and add your account again.

Reporting a problem

Send these three things — it makes issues far quicker to fix:

  1. A screenshot of the whole window
  2. What you did immediately before it went wrong
  3. The ZIP from Settings → Diagnostics → Save Diagnostics ZIP (or everything in Documents\Charticks\logs)

Report these immediately, and stop trading if you see one:

• A position at your broker that the app does not show, or the reverse
• An order the app calls successful that your broker has no record of
• Any order you did not place
• Quantity, side or product differing between the app and your broker

Square off in your broker's terminal first, then report it.

Before sending anything: crop or blur every screenshot and check that no API key, PIN, token or TOTP secret is visible. Log files have been seen to contain an Angel API key on certain errors — if you are unsure, say so when you send them, and rotate the key at your broker.
